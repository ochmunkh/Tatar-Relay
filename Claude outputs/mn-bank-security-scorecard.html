Монгол банкны дижитал аюулгүй байдал — харьцуулалт

Зөвхөн өөрийн зөвшөөрөлтэй ажиглалт дээр үндэслэсэн техник үнэлгээ · 2026-09 · цааш задруулахгүй

Ерөнхий эрэмбэ

1XacBankAECDH → AES-GCM: түр зуурын түлхүүр солилцоо + authenticated (AEAD). App-layer шифр нь жинхэнэ хамгаалалт нэмдэг.
2GolomtA−Password RSA-2048 (нэг талын, client-ээс задрахгүй) + хүчтэй MFA (SOTP + liveness/face).
3KhanbankB+App-layer шифргүй — гэхдээ TLS + богино хугацаат opaque token + anti-bot. Худал аюулгүй байдал бүтээгээгүй, шударга.
4BogdB−TLS + JSESSIONID + SMS OTP. Найдвартай суурь, гэвч SMS OTP сул (SIM-swap), anti-automation султай.
5TDBCAES-CBC (CryptoJS), түлхүүр (ecode) client талд, MAC байхгүй. "Шифрлэсэн" мэт ч client-side key тул obfuscation.
6CapitronC−AES-128-CBC, hardcoded default key + fixed IV (детерминистик), MAC-гүй, түлхүүрийг console-д логлодог. Хамгийн их "театр".
Гол дүгнэлт: TLS дээр нэмсэн app-layer шифрлэлт нь түлхүүр нь client талд байвал жинхэнэ нууцлал нэмэхгүй — зөвхөн энгийн харахаас далдална (obfuscation). Тийм болохоор "бүх юмаа шифрлэсэн" TDB/Capitron нь TLS-д найдсан Khaan/Bogd-оос илүү аюулгүй биш, харин ч худал итгэл төрүүлж, хүчин чармайлт дэмий үрдэг. Жинхэнэ хүчтэй нь XacBank (ephemeral ECDH+AEAD) ба Golomt (RSA нэг тал + хүчтэй MFA).

Юуг сайжруулах шаардлагатай

Capitron яаралтай

Bundle доторх hardcoded default key-г арилгах; fixed IV-г болих — мессеж бүрт random nonce (эсвэл AES-GCM) ашиглах (детерминистик шифр нь replay/linkability үүсгэж байна); MAC/AEAD нэмэх; түлхүүрийг console-д логлохоо болих. Суурь асуудал: түлхүүр client талд байгаа тул энэ шифр нь TLS-ээс илүү нууцлал өгөхгүй — эсвэл сервер-баталгаат ephemeral схем рүү шилжих, эсвэл зүгээр TLS-д найдах.

TDB дунд

Integrity нэмэх (AES-GCM эсвэл HMAC) — одоо MAC байхгүй тул tamper хийж болно. ecode нь client талд тул шифр нь obfuscation гэдгийг хүлээн зөвшөөрч, эмзэг талбар (password) client-ээс задрахгүй байлгах. Дээд түвшинд: TLS + зөв CSRF/anti-replay л хангалттай.

Bogd дунд

SMS OTP нь SIM-swap-д эмзэг → app-based push / TOTP / FIDO рүү шилжихийг зөвлөнө. Anti-automation (bot хамгаалалт) нэмэх. Суурь TLS/session зохион байгуулалт хэвийн.

Khanbank бага

Ерөнхийдөө шударга, зөв хандлага. base64 password нь зөвхөн encoding (TLS хамгаална). Token эргэлт (rotation) ба богино exp-ээ хадгалах. Онцын сул тал ажиглагдаагүй.

XacBank бага

Хүчтэй — ECDH+GCM хадгал. Certificate pinning (mobile) ба nonce reuse-ээс сэргийлэх талаар давхар шалгах. Загвар нь бусад банкинд үлгэр болохуйц.

Golomt бага

Хүчтэй — RSA password + liveness MFA. RSA padding нь OAEP (PKCS#1 v1.5 биш) эсэхийг батлах. Хатуу MFA-гаа хадгал.

Тайлбар: энэ үнэлгээ зөвхөн ажиглагдсан клиент-талын зан төлөв дээр үндэслэв (сервер-тал, backend хамгаалалт, WAF, монитор энд хамрагдаагүй). Khanbank/Bogd-ийн MFA-ийн бат бөх байдлыг гүнзгий шалгаагүй. Зөвхөн зөвшөөрөлтэй ажиглалт — данс/креденшл/түлхүүрийн бодит утгыг хадгалаагүй, цааш задруулахгүй.
